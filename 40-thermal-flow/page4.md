## 这次实验要验证什么

本页用两颗 10 kΩ NTC、一只 560 Ω 电阻、一只 IRLZ44N 和 Arduino 搭一个小小的热式风速计，分两段搭：

- **第 1 段**：两路 NTC 分压接 A0、A1，只测温，不加热。验证 [原理与实现篇](page2.md)「一、NTC 分压」的电压和查表法。
- **第 2 段**：加上 MOS 管开关和加热电阻，跑开关控温，把温差钉在 2 K。

要亲手看到四件事：

1. 25 °C 附近，NTC 分压点在 2.5 V 左右，每升 1 K 降约 55 mV；把 NTC 贴到一杯温水的杯壁上，电压明显下降。
2. MOS 管开透时漏极只剩不到 1 mV，加热电流 16 mA、功率约 0.145 W，电阻表面最高约 42 °C（用 N1 的读数看，不用手试）。
3. 用纸片或 USB 风扇吹，平均占空比上升；风停后回落。占空比就是风速信号。
4. 拔掉环境 NTC 补偿（程序里改一个开关），把环境 NTC 贴到温水杯壁上，读数就乱了。

## ⚠️ 安全须知

- **只用 12 V 及以下的直流电。** 本页的加热器用一只 9 V 电池或 9 V 直流适配器单独供电，Arduino 用 USB 供电。不需要任何市电设备。
- **加热器的功率和温度上限（必须遵守）：**
  - 本页的加热器是 **560 Ω、2 W 的金属膜电阻接 9 V**：电流 16.07 mA，功率 0.1446 W，只用了额定功率的 7.2 %。
  - 按电阻手册的热阻 75～115 K/W 算，即使程序出错、加热器 100 % 一直开着，在 25 °C 室温下电阻表面最高 **35.8～41.6 °C**（按 9.0 V 算；新电池 9.6 V 时 37.3～43.9 °C），低于 45 °C 的切断线，也远低于会烫伤的温度。不过手册的热阻是焊在电路板上的值，插在面包板上、引线较长时实际热阻可能更大［待核实］，所以程序的 45 °C 切断不能省。即便如此，**温度一律看 N1 的读数或用测温探头、万用表测温档量，不要用手去试。**
  - 程序里还有**软件过温切断**：加热 NTC 读到 **45 °C** 以上，或 NTC 断线、短路，立刻关加热并锁死，直到按复位键。
- **47 Ω 一律不用。** 47 Ω 接 12 V 是 3.06 W，超过 2 W 额定；接 9 V 是 1.72 W，表面温升可达 129～198 K；网上常见的“47 Ω 接 5 V”也有 0.53 W，表面会到 65～86 °C，会烫伤。
- **手上没有 560 Ω 时**，用 680 Ω～1 kΩ 之间任何一只 2 W 电阻接 9 V（先按 $P = V^2/R$ 算，最坏表面温度不超过 45 °C）：680 Ω 是 0.119 W、最坏 38.7 °C；1 kΩ 是 0.081 W、最坏 34.3 °C（`code/40_sim.py` 第 8 部分）。阻值越大越安全，代价是无风占空变大、量程变小（[原理与实现篇](page2.md)例 2）。
- **温水杯**：步骤里用来给 NTC 加热的温水先用测温探头或万用表测温档量，**不超过 40 °C**；只用干燥的杯子外壁去贴 NTC，杯子下垫毛巾，不要把水洒到面包板上。
- **NTC 的上限**：NTCLE100E3 连续工作温度最高 125 °C；本实验远低于它，但不要把 NTC 直接贴在烙铁、灯泡等发热体上。
- **共地**：9 V 电源的负极必须接到面包板 0 V 轨，和 Arduino GND 连通，否则 D9 控制不了 MOS 管。9 V 正极只能接下方 +9 V 轨，**千万不要碰到 Arduino 的 5V 或 A0、A1**（Arduino 引脚最高只能承受 5 V）。
- **接线、改线之前先断电**：拔下 9 V 电池扣和 USB 线。
- **N1 和 $R_H$ 只用绝缘胶带包**：铝箔胶带导电，一旦碰到裸引脚，就会把 $R_H$ 那头的 +9 V 接到 N1 那头的 A0 节点（第 21 列上下半），烧坏 Arduino。用 Kapton 一类的绝缘耐热胶带，只缠两个元件的本体，引脚露在外面互不接触。
- 如果闻到焦味、看到元件变色或冒烟，或 N1 读数超过 45 °C，立刻拔掉 9 V 电池，多半是电阻用错了（色环看错）或 9 V 接到了不该接的地方。

「应该读到」来自 Vishay 手册的 NTC 公式和 SPICE（25 °C 时 2.500 V，45 °C 时 1.521 V）。室温不一定是 25 °C，所以下面按室温给范围。本表黑表笔都接 0 V 轨。

| 2 | 室温下 ① A1 分压 | e7 | 0 V 轨 | 直流 20 V | 20 °C 约 2.78 V，25 °C 约 2.50 V，30 °C 约 2.23 V | 接近 5 V：NTC 没插好；接近 0： $R_S$ 没插好 |

**对照看**：图 40-p4-4 里“D9 → $R_G$ → 栅极”在面包板上是 j19（D9 进来）→ $R_G$ 插 g19–g23 → 绿线 h23 → h27 → IRLZ44N 的 G 脚 f27； $R_{PD}$ 也插在第 27 列（j27），所以栅极、下拉电阻、绿线共用第 27 列下半。④ 量 j23（和 g23、h23 同属第 23 列下半）：i23 被 $R_H$ 的本体盖住，表笔插不进去，所以换到同一列空着的 j23。

“ $R_H$ 一端接 +9 V、另一端接漏极”在面包板上是： $R_H$ 插 i21–i25，j21 接 +9 V 轨，g25 一根短绿线跨到 g28（D 脚）。

注意第 21 列**下半**是 +9 V，**上半**是 A0 节点，两者隔着凹槽不相通。最危险的错误是把 +9 V 那根橙线插到第 21 列上半（a21–e21）：9 V 会直接加到 A0 上烧坏 Arduino。 $R_H$ 插到上半（例如空着的 d21–d25 或 e21–e25 那一排）不会把 9 V 送进 A0，但它会和 N1 并在一起（第 25 列上半经黑线接 0 V），加热器不通电，读数也全错。

N1 和 $R_H$ 在面包板上相邻（第 21～25 列，凹槽两侧），把 N1 的引脚轻轻弯过去，让它的头贴在 $R_H$ 的本体上，用 Kapton 绝缘胶带只在两个本体上缠两圈（图 40-p4-3 两个橙色虚线小框）。N1 的引脚（第 21 列上半是 A0）和 $R_H$ 的引脚（第 21 列下半是 +9 V）绝不能互相碰到，也不能被导电的东西连起来。

1. **断电。** 拔 USB，不要接 9 V。
2. **插 MOS 管。** IRLZ44N 印字面朝自己，三只脚从左到右 G、D、S 插 f27、f28、f29。
3. **栅极。** $R_G$ 100 Ω 插 g19–g23；绿线 h23 → h27； $R_{PD}$ 100 kΩ 从 j27 接到下方 0 V 轨；绿线从 Arduino D9 接 j19。
4. **加热器。** $R_H$ 560 Ω 插 i21–i25（**下半**）；橙线 j21 → 下方 +9 V 轨；绿线 g25 → g28；黑线 j29 → 下方 0 V 轨。
5. **贴 N1。** 把 N1 头部贴在 $R_H$ 本体中间，用 Kapton 绝缘胶带缠紧，只缠本体；缠完看一眼两个元件的引脚有没有碰在一起。
6. **检查后通电。** USB 和 9 V 都不接，用万用表电阻挡（20 kΩ 挡）量两处，**表笔方向要照下面写的接**：
   - **红笔 +9 V 轨、黑笔 0 V 轨**：中间串着 $R_H$ 和关断的 MOS 管，应显示超量程（或几百 kΩ 以上）。如果只有 560 Ω 左右，说明 MOS 管的 D、S 插反了、管子已击穿，或 $R_H$ 那头误插到了 0 V。
   - **红笔 +9 V 轨、黑笔 e21（② A0 节点）**：也应超量程。如果读到接近 0 Ω，说明 +9 V 橙线插到了第 21 列上半，和 A0 节点直接连通了，通电后 9 V 会直接进 A0，必须先改线。注意： $R_H$ 误插到上半时，这一项和上一项仍然都是超量程，万用表查不出来，所以还要用眼睛确认 $R_H$ 两只脚在 i21、i25（凹槽下方），橙线在 j21。
   - 为什么要规定方向：IRLZ44N 内部 S 到 D 之间有一只“体二极管”（MOS 管制造时自带的）。表笔反过来（黑笔 +9 V、红笔 0 V）时，万用表电阻挡输出的小电流正好让这只二极管导通，完好的管子也会读到 560 Ω 加一只二极管压降对应的“阻值”，新手会误以为接错。所以只按上面的方向量；方向对了还读到低阻，才是真有问题。

   确认后插 USB，上传程序，最后接 9 V。

画图脚本会检查栅极、下拉、加热器、漏极、源极的每一处连接，并确认 +9 V 轨和 +5 V 轨、0 V 轨都不相连；接错一处图就画不出来。

### Arduino 程序

> **第一次用 Arduino？** 上传方法见 [35 程控增益与 AGC · 动手实验篇](../35-pga-agc/page4.md)「最小必要知识：Arduino 上手」。

程序做五件事：① 读 A0、A1，用查表把 ADC 读数换成温度；② 开机前 10 s 不加热，记下两颗 NTC 的读数差当“零点”；③ 迟滞开关控温（1.8 / 2.2 K）；④ 统计最近 3 个开关周期的平均占空；⑤ 过温、断线保护。

```cpp
// 40 热式风速计：迟滞开关控温（温差 2 K），输出平均占空比
const int   PIN_HEAT = 9;
const float T_SET = 2.0, HYS = 0.2;   // 温差门限 1.8 / 2.2 K
const float T_CUTOFF = 45.0;          // 加热 NTC 过温切断
const bool  COMPENSATE = true;        // false = 不用 N2 实时补偿（思考题用）
const int   MODE = 0;                 // 0 开关控温；1 恒功率 60 %；2 加热 100 % 测试（上电后第 40 s 自动停）

// 查表：10、15、...、60 °C 时的 ADC 读数（R_S = 10 kΩ，Vishay 手册公式）
const float CNT[] = {681.2, 625.5, 568.6, 512.0, 457.0, 404.7, 356.0, 311.5, 271.4, 235.6, 204.1};
const int   NT = 11;

float cntToT(float c) {               // ADC 读数 → 温度（°C），两点之间按直线插值
  if (c >= CNT[0]) return 10.0;
  for (int i = 0; i < NT - 1; i++)
    if (c >= CNT[i + 1]) return 10.0 + 5.0 * i + 5.0 * (CNT[i] - c) / (CNT[i] - CNT[i + 1]);
  return 60.0;
}
float readCnt(int pin) { long s = 0; for (int i = 0; i < 16; i++) s += analogRead(pin); return s / 16.0; }

bool fault = false, heat = false;
float zero = 0, amb0 = 25.0;
unsigned long tOn = 0, tCycle = 0, tLastPrint = 0, tLastSwitch = 0;
float duty[3] = {0, 0, 0}; int nd = 0;
int skip = 2;                         // 开机后前 2 个周期不准，不计入 duty3

void setHeat(bool on) { heat = on; digitalWrite(PIN_HEAT, on ? HIGH : LOW); }

void setup() {
  pinMode(PIN_HEAT, OUTPUT); setHeat(false);
  Serial.begin(9600);
  float s = 0, a = 0;                  // 前 10 s 不加热：记零点和开机时的环境温度
  for (int i = 0; i < 100; i++) {
    float t1 = cntToT(readCnt(A0)), t2 = cntToT(readCnt(A1));
    s += t1 - t2; a += t2; delay(100);
  }
  zero = s / 100; amb0 = a / 100;
  Serial.print("zero(K)="); Serial.println(zero, 3);
  tCycle = tLastSwitch = millis();
}

void loop() {
  float c1 = readCnt(A0), c2 = readCnt(A1);
  float t1 = cntToT(c1), t2 = cntToT(c2);
  // 保护：过温、NTC 断线（读数接近 1023）或短路（接近 0）→ 关加热并锁死
  if (t1 > T_CUTOFF || c1 > 1000 || c1 < 20 || c2 > 1000 || c2 < 20) fault = true;
  if (fault) { analogWrite(PIN_HEAT, 0); heat = false;
               if (millis() - tLastPrint > 1000) { Serial.println("FAULT: heater off, press reset"); tLastPrint = millis(); }
               return; }

  float ref = COMPENSATE ? t2 : amb0;
  float dT = t1 - ref - zero;
  unsigned long now = millis();

  if (MODE == 1) analogWrite(PIN_HEAT, 153);              // 153/255 = 60 %
  else if (MODE == 2) analogWrite(PIN_HEAT, now < 40000UL ? 255 : 0);
  else {
    if (!heat && dT < T_SET - HYS) {                      // 关 → 开：一个周期结束
      unsigned long period = now - tCycle;
      if (period > 0) {
        if (skip > 0) skip--;
        else { duty[nd % 3] = 100.0 * tOn / period; nd++; }
      }
      tCycle = now; tOn = 0; tLastSwitch = now; setHeat(true);
    } else if (heat && dT > T_SET + HYS) {
      tOn = now - tCycle; tLastSwitch = now; setHeat(false);
    }
  }

  if (now - tLastPrint >= 1000) {
    tLastPrint = now;
    float avg = 0; int k = nd < 3 ? nd : 3;
    for (int i = 0; i < k; i++) avg += duty[i];
    if (k) avg /= k;
    Serial.print(now / 1000); Serial.print(" s  N1="); Serial.print(t1, 2);
    Serial.print("  N2="); Serial.print(t2, 2); Serial.print("  dT="); Serial.print(dT, 2);
    Serial.print("  heat="); Serial.print(heat);
    Serial.print("  duty3="); Serial.print(avg, 1);
    if (MODE == 0 && heat && now - tLastSwitch > 120000UL) Serial.print("  OVER-RANGE");
    Serial.println();
  }
  delay(100);
}
```

几点说明：

- 断线保护很重要：N1 断线时分压点被 $R_S$ 拉到 5 V，读数接近 1023，查表会读成“很冷”，如果没有这条判断，程序会让加热器一直开着。
- 加热器连续开着超过 120 s 还碰不到上门限 2.2 K，就打印 `OVER-RANGE`（超量程）。按模型，开关控温的量程上限约 2.6 m/s（全开时温差刚好 2.2 K），对应 [参数与调试篇](page3.md)「二」里 3 m/s 的情况。
- `MODE = 2` 只用来做下表的第 7 步（量加热电流）：上电后先 10 s 不加热（记零点），接着全开约 30 s，到上电后第 40 s 自动关断。
- 开机后前 2 个开关周期不计入 duty3：第一个周期从“刚上电、温差为 0”开始，开、关时间都不正常，算进去会把平均占空拉偏。

### 第 2 段测量表

「应该读到」来自 SPICE（加热电流、MOS 管压降）和 Python 热模型（温升、占空，示意参数，你的数值会因胶带贴法、气流不同而偏离，看趋势即可）。黑表笔大多接 0 V 轨，第 7 步例外（量 $R_H$ 两端）；读串口的步骤不用表笔，记作“—”。

| 步骤 | 测什么 | 红表笔 | 黑表笔 | 挡位 | 应该读到 | 读不到时先查 |

| 1 | +9 V 轨 | +9 V 轨 | 0 V 轨 | 直流 20 V | 8.5～9.6 V（新电池偏高） | 0：电池扣没接好 |
| 2 | `MODE = 0` 上传，前 10 s 串口打印 zero | 串口 | — | — | 绝对值小于 0.3 K | 很大：N2 离你的身体或杯子太近，或两颗 NTC 公差大 |

常见的“怪现象”和对策：

- **不开风扇，dT 也在 ±0.5 K 里慢慢漂。** 空调、开门、人走动都会带起气流，人体靠近也会烤热 NTC。用一截纸筒或硬纸板卷成的风道罩住探头，读数取 30 s 平均。
- **A0 读数每次跳好几个字。** 10 kΩ 分压点阻抗较高，长引线容易拾取干扰。**先拔 9 V 电池扣和 USB**，再在 e21（② 分压点）到 0 V 轨之间加一只 100 nF 电容（见图 40-p4-2 灰色点线，选装），把 N2 的两根引线绞在一起，远离 9 V 线。程序里每次读 16 次取平均，已经帮了一半。
- **N2 读数也跟着加热升高。** N2 离加热器太近，或在它的下风处。把 N2 挪到上风处、离 $R_H$ 至少 5 cm，不要和 $R_H$ 贴在同一块胶带上。断开 9 V 时两颗 NTC 应读数一致；加热后 N2 升高不应超过约 0.5 K。
- **碰一下胶带，dT 就变。** N1 和 $R_H$ 之间的接触热阻随压力变化。胶带缠紧后不要再去按压它。
- **电池用了一阵，占空整体偏高。** 加热功率是 $D \cdot V^2 / R_H$ ，电池从 9.6 V 降到 8.5 V，同样占空下功率少了约 22 %，程序只好开更久。标定前后各量一次 +9 V 轨；要长期用，换 9 V 适配器。
- **为什么 $R_H$ 可以插在面包板上？** 因为本页的 560 Ω 方案最坏情况只有约 42 °C，面包板塑料承受得了。换成大功率加热器时，必须把它装在陶瓷片或木片上，不能插在面包板上。

几处值得算一算：

- **第 7 步算功率。** 若读到 8.98 V， $R_H$ 实测 556 Ω，则 $I$ = 8.98 / 556 = 16.15 mA， $P$ = 8.98² / 556 = 0.145 W。乘以你测到的平均占空，就是平均加热功率：30 % 时约 43 mW。
- **第 6 步和第 9 步的比值。** 无风 30 %、有风 65 %，加热功率涨了一倍多，对应散热能力从约 20 mW/K 涨到约 48 mW/K（[直觉篇](page1.md) 的 King 曲线）。
- **为什么步骤 11 把 N2 贴杯壁反而“不受影响”？** 不补偿时程序根本不看 N2 的实时读数，这恰恰是它的问题：真正的气体温度变了，它也不知道。比较两种设置下的现象，就明白为什么要用 N2 实时补偿。

### 标定（选做）

有风速计的话，在 3～5 个风速下记录稳态 duty3，把这些点填进下面 Python 程序的 `CAL`，就得到你自己探头的“占空 → 风速”曲线。曲线弯的地方（低风速段）多放一个点。

## 没有示波器怎么办

本页本来就是慢变化，万用表和串口监视器足够：

- **串口绘图器**：Arduino IDE 的“工具 → 串口绘图器”可以把 dT 和 heat 画成曲线，相当于一台慢速示波器，能看到 [参数与调试篇](page3.md)「一、开关控温」那张图里的锯齿。
- **PWM 波形**：`MODE = 1` 时 D9 是 490 Hz 方波，万用表直流挡量 ④ 读到的是平均值，约 0.6 × 5 V = 3.0 V；这正是“平均值 = 占空 × 幅度”的验证。
- 看不到的：MOS 管开关瞬间的边沿（微秒级），本实验不需要。

## 用 Python 核对你的读数

把你量到的数填进第一部分（下面是示例值），代码算出加热电流和功率，把每个实测值和计算值并排比较（偏差超过 10 % 会提示先查哪里；漏极电压太小，只看是否低于 10 mV），再把 ADC 读数换成温度，并用你的标定点拟合占空 → 风速曲线。示例标定点按[参数与调试篇](page3.md)「二、标定」的结论，在低风速段多放了 0.5 m/s 一个点；拟合用二次多项式，5 个点比 3 个系数多 2 个，打印出的残差才能说明拟合好不好。

```python
import sys, pathlib
sys.path.insert(0, str(pathlib.Path("code/figs").resolve()))  # 在仓库根目录运行
import numpy as np

# ---- 1. 你量到的值（示例值，换成你自己的）----
V_H        = 8.98     # 第 7 步：R_H 两端电压（V）
R_H        = 556.0    # 搭之前用电阻挡量的 R_H（Ω）
V_gate     = 4.98     # 第 3 步：④ 栅极（V）
V_drain_on = 0.00032  # 第 4 步：③ 漏极，加热开（V）
duty0      = 30.5     # 第 6 步：无风平均占空（%）
V_A1       = 2.51     # 第 1 段第 2 步：万用表量的 ①（V）
cnt_room   = 509      # 同一时刻串口里 A1 的 ADC 读数
CAL = [(0.0, 30.5), (0.5, 55.0), (1.0, 63.0), (2.0, 79.0), (2.5, 86.0)]   # (风速 m/s, 平均占空 %)

def check(name, meas, calc, hint):
    dev = (meas - calc) / calc * 100
    print(f"{name}：实测 {meas:.4g}，计算 {calc:.4g}，偏差 {dev:+.1f} %")
    if abs(dev) > 10:
        print(f"  偏差超过 10 %，先查：{hint}")

# ---- 2. 加热电流、功率、温升上限 ----
I = V_H / R_H
P = V_H**2 / R_H
check("加热电流 mA", I * 1e3, 16.07, "MOS 管是否开透、R_H 色环是否看错")
check("④ 栅极 V", V_gate, 4.995, "D9 线、R_G 是否接在 j19、g19–g23")
print(f"③ 漏极（开）：实测 {V_drain_on*1e3:.2f} mV（SPICE 0.34 mV）")   # 太小，不用相对偏差
if V_drain_on > 0.01:
    print("  超过 10 mV，先查：MOS 管型号（要 IRLZ44N）、S 脚是否接 0 V 轨")
check("无风平均占空 %", duty0, 29.7, "胶带是否缠紧、N2 是否离加热器 ≥ 5 cm、+9 V 轨电压")
check("① 万用表 vs ADC 换算 V", V_A1, cnt_room * 5 / 1024, "Arduino 5V 是否偏低、A1 线是否接在 a7")
print(f"无风平均功率 {P*duty0/100*1e3:.1f} mW")
for rth in (75, 115):
    print(f"热阻 {rth} K/W：100 % 一直开着的表面温度 {25 + P*rth:.1f} °C（必须 < 45 °C）")

# ---- 3. ADC → 温度（和 Arduino 同一张表）----
T_TAB = np.arange(10, 65, 5)
CNT = np.array([681.2, 625.5, 568.6, 512.0, 457.0, 404.7, 356.0, 311.5, 271.4, 235.6, 204.1])
t_room = np.interp(cnt_room, CNT[::-1], T_TAB[::-1])
print(f"A1 读数 {cnt_room} → 室温 {t_room:.2f} °C")

# ---- 4. 标定曲线：占空 → 风速（二次多项式；点数比阶数多 2，残差才有意义）----
v = np.array([c[0] for c in CAL]); d = np.array([c[1] for c in CAL])
deg = min(2, len(CAL) - 2)
coef = np.polyfit(d, v, deg)
for di in (45.0, 70.0):
    print(f"平均占空 {di:.0f} % → 风速约 {np.polyval(coef, di):.2f} m/s")
res = v - np.polyval(coef, d)
print("标定点残差（m/s）：", np.round(res, 3))
```

### 思考题

**1. 为什么程序要先判断“NTC 断线”，而不只是判断“温度超过 45 °C”？**

<details><summary>答案</summary>

NTC 断线时，分压点被 $R_S$ 拉到 5 V，ADC 读数接近 1023，查表得到的是“很冷”（10 °C 以下）。只看“超过 45 °C”永远不会触发，而温差显得很小，开关控温会让加热器一直开。本页的 560 Ω 加热器即使一直开也只到约 42 °C，但换成大功率加热器时，这就是火灾隐患。安全保护要考虑“传感器自己坏了”的情况。

</details>

**2. 如果把设定温差从 2 K 改成 1.5 K（参数与调试篇的表里没有这一行），无风时占空会变成多少？能测的最大风速怎么变？1 个 ADC 字的相对误差呢？**

<details><summary>答案</summary>

按[参数与调试篇](page3.md)的模型，无风占空和设定温差成正比：28.3 % × 1.5 ÷ 2 ≈ 21.3 %（PI 理想值，模型 21.26 %）。功率够用的风速变大到 5 m/s 以上（模型只扫到 5 m/s），但本节的标定点最高只到 2.5 m/s（第一部分的 CAL）：超出标定范围的那一段没有标定点，拟合曲线外推不可信，所以能用的量程仍由标定决定，多出来的功率余量用不上。代价是 1 个 ADC 字（约 0.089 K）的相对误差从 4.5 % 升到 0.089 ÷ 1.5 ≈ 5.9 %。设定温差是“分辨率”和“量程”之间的取舍。

</details>

**3. 为什么开关控温的平均占空要等 3 个周期才更新？能不能每个周期都更新？**

<details><summary>答案</summary>

单个周期里，开和关的时间会因为 ADC 噪声、气流的小扰动而来回跳，单个周期的占空比很“毛”。取最近 3 个周期平均，用速度换平稳。代价是更新慢：每个周期约 20～28 s，3 个就是 1 分钟左右，所以模型里 t90 是 60～84 s。想又快又稳，就要换 PI 控制（[参数与调试篇](page3.md)「四」）。

</details>

**4. 工业热式流量计的 CTA 能在毫秒级响应，你的面包板版本为什么做不到？**

<details><summary>答案</summary>

工业热膜同时是加热器和测温元件，热容极小，运放直接闭环。面包板版本的 N1 贴在加热电阻外面，热量要穿过胶带和 NTC 的环氧外壳，NTC 自己的热时间常数约 15 s；控制回路再快，也快不过传感器“感觉到”温度变化的速度。

</details>

- 我能算出 560 Ω 接 9 V 的电流和功率，并说出为什么不能用 47 Ω 接 12 V。
- 我能说出 MOS 管开透时漏极为什么只剩零点几毫伏。
- 我能解释为什么恒温差法里“平均占空”就是风速信号。
- 我能说出环境 NTC 的作用，以及程序里过温、断线保护分别防什么。

## 小结

- 第 1 段：两路 NTC 分压，25 °C 约 2.5 V，每 K 约 55 mV；查表插值就能在 Arduino 上测温。
- 第 2 段：IRLZ44N 低边开关 + 560 Ω / 9 V 加热器，导通 16.07 mA、0.1446 W，最坏情况表面约 42 °C，另有 45 °C 软件切断和断线保护。
- 迟滞开关控温把温差钉在 1.8～2.2 K，平均占空随风速升高；环境 NTC 实时补偿不能省。
- 面包板版本受 NTC 约 15 s 热时间常数限制，响应是几十秒级；工业 CTA 用热膜 + 运放电桥做到毫秒级。
