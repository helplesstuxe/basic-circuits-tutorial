37 过零检测与超声波时差 · 动手实验篇

上一页：参数与调试篇 · 直觉篇 · 原理与实现篇 · 参数与调试篇 · 本页：动手实验篇 · 下一页：38 同步检波 · 直觉篇 · 前置节点：10 电压比较器 · 动手实验篇、12 电压跟随器 · 动手实验篇、29 上拉/下拉电阻与电平转换 · 动手实验篇、36 施密特整形与频率/脉冲计数 · 动手实验篇

这次实验要验证什么

用一对 40 kHz 超声波探头、一块 Arduino Uno 和三片常见芯片（TL072、LM393、74HC74），搭一个「先武装、再过零」的超声波计时器，用风扇当「风」。要验证 原理与实现篇 和 参数与调试篇 的四个结论：

  1. 读数随间距成直线：间距每多 1 mm，计时多约 2.913 µs，斜率倒过来就是声速（约 343 m/s）；
  2. 风能被量出来：每个方向都读「关 → 开」，顺风方向开减关约 −5 µs、逆风方向约 +5 µs，两者相差约 10 µs（3 m/s 的风）；
  3. 门限放错会整周期跳：转门限电位器，读数不是慢慢变，而是一跳 25 µs；
  4. 回波大小晃一晃，读数不动：门限放在台阶中间时，用手在旁边挥动、轻轻偏转探头，读数基本不变。

主要读法是串口监视器：程序每 0.5 s 打印一次 t_us，分辨到 62.5 ns 再取 100 次平均，而且不受电源电压影响。最核心的两条（1 和 2）也能只用万用表验证：程序让 74HC74 的 /Q2 脚在每一轮里「从开始发射到捕获」这段时间输出高电平，万用表直流挡读到的平均电压正比于这段时间，V5 = 5.00 V 时每 1 µs 约 1 mV。两种读法可以互相核对。

页面里写的绝对数值（例如 707.79 µs）来自 Q = 15 的示意回波模型，你的实测值可能差几十微秒；但斜率和风造成的差不依赖这个模型，应该基本对得上。

⚠️ 安全须知

  • 全程不超过 12 V 直流：模拟部分用一只 12 V 直流电源适配器（插墙的是适配器本身，面包板上只有 12 V 直流），Arduino 用电脑 USB 供电。TL072 至少要 10 V 才能让 6 V 的中点参考 V_MID 留够余量（见参数与调试篇第五节），所以不能用 9 V 电池代替。
  • 两只 2.2 kΩ 上拉电阻只能接下方 +5 V 轨（Arduino 5 V），绝不能接上方 +12 V 轨。LM393 是开集电极输出，高电平就等于上拉电压；Q2 直接进 Arduino D8，ATmega328P 引脚电压不能超过 VCC + 0.5 V，即 5.5 V。
  • 74HC74 的 14 脚（VCC，孔 a40）用一根红色跳线接下方 +5 V 轨，千万别插上方 +12 V 轨：74HC74 的推荐电源电压最高 6 V，12 V 会烧坏它，还会把 12 V 送进 Arduino。
  • LM393 的输入要低于 VCC − 1.5 V（全温度范围 VCC − 2 V）。本电路输入都在 6 V 上下几百毫伏，12 V 供电时上限 10.5 V，余量充足。
  • Arduino 每个引脚最多 40 mA：D3、D11 一定要各串一只 150 Ω（棕绿棕），不要省掉，也不要换成 100 Ω（峰值会到 50 mA）。
  • 40 kHz 超声波人耳听不见，但声压不小：不要把发射探头贴近耳朵，也不要对着宠物（狗、猫听得见）。
  • 风扇必须带网罩，手指、头发、探头引线都远离扇叶；不用的时候关掉。风扇用单独的手机充电器供电，不要插在给 Arduino 供电的同一台电脑上（原因见第 9 步）。
  • 不要用手摸芯片或电阻试温度。如果 Arduino 反复复位、串口断开，或闻到焦味，立刻拔掉 12 V 适配器和 USB，再对照图检查。
  • 每一步改线、插拔元件之前都要断电：先拔 12 V 适配器，再拔 USB。改完先对照图检查，先接 USB、再接回 12 V 适配器。只挪动探头、转电位器、开关风扇不碰面包板，可以带电做。第 6 步的手动检验只接 USB、不接 12 V，而且只用一根一端已插在 GND 轨的跳线去碰指定的孔。
  • Cm 是 10 µF 电解电容，长脚（+）插 j6，短脚（−，外壳白色条纹一侧）接下方 GND 轨。接反会发热、鼓包。

先上传程序（第 1 步）

在接任何线之前，先只用 USB 把 Arduino 接到电脑，上传下面的程序，然后拔掉 USB。

⚠️ 下面的程序未经运行验证：我们没有在真实的 Arduino 上跑过它，只核对过寄存器名称和时序计算（code/37_sim.py）。上传后如果串口没有输出，先检查波特率是否设为 115200。

// 未经运行验证
// 37 超声波时差：D3、D11 反相发 8 个 40 kHz 周期；D4 清零兼盲区；D8（ICP1）捕获 Q2 的上升沿
// Timer1 不分频，一格 62.5 ns；一轮 80000 格 = 5 ms；每 100 轮打印一次平均值

const uint16_t HALF  = 200;     // 半个 40 kHz 周期 = 200 格 = 12.5 µs
const uint8_t  NHALF = 16;      // 8 个周期 = 16 次翻转
const uint16_t BLANK = 5600;    // 盲区 350 µs
const uint16_t TAIL  = 14464;   // 溢出（65536）后再等这么多格，凑满 80000
const uint8_t  NAVG  = 100;     // 100 轮打印一次（0.5 s）

uint32_t sum = 0;
uint16_t tmin = 65535, tmax = 0;
uint8_t  n = 0, miss = 0;

void setup() {
  Serial.begin(115200);
  pinMode(3, OUTPUT); pinMode(11, OUTPUT); pinMode(4, OUTPUT); pinMode(8, INPUT);
  digitalWrite(3, LOW); digitalWrite(11, LOW); digitalWrite(4, LOW);
  TCCR1A = 0;                             // 普通计数模式
  TCCR1B = (1 << ICES1) | (1 << CS10);    // 上升沿捕获，不分频（16 MHz）
  TIMSK1 = 0;                             // 不用中断，只看标志位
}

void loop() {
  noInterrupts();                         // 发射和盲区期间不让别的中断插队
  PORTD &= ~(1 << 4);                     // D4 = 0：两个触发器清零，/Q2 变高
  TCNT1 = 0;
  TIFR1 = (1 << ICF1) | (1 << TOV1);      // 清掉旧标志（写 1 清零）
  PORTD |= (1 << 3);                      // D3 = 1、D11 = 0：第一个半周期
  for (uint8_t k = 1; k < NHALF; k++) {
    while (TCNT1 < k * HALF) {}
    PIND = (1 << 3);                      // 往 PINx 写 1 = 翻转：D3 = PD3
    PINB = (1 << 3);                      // D11 = PB3
  }
  while (TCNT1 < NHALF * HALF) {}
  PORTD &= ~(1 << 3); PORTB &= ~(1 << 3); // 发完，两脚都回 0
  while (TCNT1 < BLANK) {}
  TIFR1 = (1 << ICF1);                    // 丢掉盲区里的捕获
  PORTD |= (1 << 4);                      // D4 = 1：放开清零，开始等回波
  interrupts();

  while (!(TIFR1 & (1 << TOV1))) {}       // 等到 4.096 ms 溢出
  bool got = TIFR1 & (1 << ICF1);
  uint16_t t = ICR1;                      // 硬件在 Q2 上升沿那一刻抄下的值
  if (got) {
    sum += t; n++;
    if (t < tmin) tmin = t;
    if (t > tmax) tmax = t;
  } else {
    miss++;
  }
  if (n + miss >= NAVG) {
    float avg = n ? (float)sum / n : 0;
    Serial.print("ICR1=");   Serial.print(avg, 1);
    Serial.print("  t_us="); Serial.print(avg / 16.0, 2);
    Serial.print("  min=");  Serial.print(tmin);
    Serial.print("  max=");  Serial.print(tmax);
    Serial.print("  miss="); Serial.println(miss);
    sum = 0; n = 0; miss = 0; tmin = 65535; tmax = 0;
  }
  while (TCNT1 < TAIL) {}                 // 凑满 5 ms
}

max − min 是这 100 轮里最晚和最早的差：正常时只有几格；如果接近 400 格（25 µs），说明在跳周期。miss 是没捕获到的轮数，正常应为 0。

① V_MID：图 37-p4-2 里 R1、R2 分压后进 TL072 A，输出就是 V_MID。在图 37-p4-1 上，一根红跳线从上方 +12 V 轨第 3 列接 g3，R1 在 h3–h5、R2 从 i5 到下方 GND 轨、Cm 在 j6；g5–g6 和 h6→g10 把分压点送到第 10 列下半（3 脚 IN+A）；h8–h9 把 1 脚（OUTA）接回 2 脚，组成跟随器；i9→i20 把 V_MID 送到第 20 列（表笔点 ③）。e20–f20 让第 20 列上下两半都是 V_MID。

② 接收放大：接收探头两根线插 a11（5 脚 IN+B）和 a20（V_MID）；Rb 100k 在 b11–b20。Rf 100k 从 c9（7 脚 OUTB）到 c13，d10→e13 把第 13 列接回 6 脚 IN−B；Rg 10k 在 d13–d17，Cg 100 nF 在 c17–c20 回到 V_MID。放大输出经 a9→a22 到第 22 列（表笔点 ①），e22–f22 让上下两半都有。

③ 两只比较器：g22→g25 把放大输出送进 LM393 的 2 脚（IN−A）。电位器的三只脚插在 h31、h32、h33；门限网络从 V_MID 出发，跳线 h20→i31 接到电位器的一端（i31 和 h31 在同一列，不和电位器的脚抢同一个孔），电位器另一端 h33 经 100k（g33–g36）到第 36 列，再从上方 +12 V 轨第 37 列用红跳线接 f36；中间脚经 i32→i26 送进 3 脚（IN+A，表笔点 ②）。过零比较器：10k c22–c27 进 5 脚（IN+B），10k d20–d26 进 6 脚（IN−B），R_HY 4.7M 在 a25–a27。

④ 上拉与触发器：LM393 的 1 脚（OUTA）经 j24 的 2.2k 上拉到下方 +5 V，i24→i43 接 74HC74 的 4 脚 /PRE1；7 脚（OUTB）经 b25→b29 引到第 29 列上半，e29–f29 把第 29 列上下两半连通，j29 的 2.2k 上拉到下方 +5 V；c29→c43 接 11 脚 CLK2。74HC74 的 5 脚 Q1 经 g44→a42 接 12 脚 D2；9 脚 Q2 经 a45 接 D8；8 脚 /Q2 在第 46 列上半（表笔点 ④）。

⑤ 电源：TL072 的 8 脚 a8、LM393 的 8 脚 a24 接上方 +12 V 轨，Cd 各自从 b8、b24 接上方 GND 轨；TL072 的 4 脚 j11、LM393 的 4 脚 j27 接下方 GND 轨。74HC74 的 14 脚 a40 用红色跳线接下方 +5 V 轨，Cd 从 c40 接上方 GND 轨。

第 2 步：放芯片、接电源（断电）

（第 1 步是上面的上传程序。）确认 USB 和 12 V 适配器都没接。三片芯片都跨在中间凹槽上，缺口朝左，1 脚在左下角（f 排），逆时针数：TL072 占第 8–11 列，LM393 占第 24–27 列，74HC74 占第 40–46 列。

  • 按 ⑤ 接好三片芯片的电源和三只 Cd；
  • 12 V 适配器的 + 接上方 +12 V 轨，− 接上方 GND 轨；第 1 列把上下两条 GND 轨连通；
  • Arduino 的 5V 接下方 +5 V 轨、GND 接下方 GND 轨。

接回电源（先 USB、再 12 V），用 20 V 挡确认：上方两轨之间约 12 V，下方两轨之间约 5 V（记下这个 V5，后面要用）。用表笔碰一下 a40 和下方 GND 轨，应是约 5 V，不是 12 V。

第 3 步：V_MID（断电）

断电，按 ① 插 R1、R2、Cm 和六根跳线：+12 V→g3（红）、g5–g6、h6→g10、h8–h9、i9→i20、e20–f20。接回电源，表笔点 ③ 应读约 6.0 V。

第 4 步：接收放大（断电）

断电，按 ② 接接收探头、Rb、Rf、Rg、Cg 和跳线 d10→e13、a9→a22、e22–f22。接回电源，表笔点 ① 的直流电压也应约 6.0 V（Cg 挡住直流，直流上只是跟随 V_MID）。如果读数贴近 12 V 或贴近 0 V，说明 Cg 没插对或 Rb 没接到 V_MID，运放被直流放大到顶了。

第 5 步：两只比较器和门限（断电）

断电，按 ③ 插电位器、100k、两只 10k、R_HY 和两只 2.2k 上拉（只接 +5 V 轨），以及跳线 g22→g25、h20→i31、+12 V→f36（红）、i32→i26、b25→b29、e29–f29（共 6 根跳线，和图 37-p4-1 一致；c22–c27、d20–d26 是那两只 10k 电阻，不是跳线）。

先顺手检查两只上拉：只插 USB，不接 12 V 适配器。这时 LM393 不工作，它的两个输出只靠 2.2k 上拉，都应是约 5 V。黑表笔放 GND 轨，红表笔依次碰 h24、h29、c29（j29 插着 2.2k 的脚，表笔改碰同半列的 h29，g29、i29 也行），三处都应约 5 V。h24 约 0 V：j24 的 2.2k 没接到下方 +5 V 轨；h29 也约 0 V：j29 的 2.2k 没接好；h29 约 5 V 而 c29 约 0 V：多半是 e29–f29 没插，第 29 列上下两半没接通，万用表的 10 MΩ 内阻把悬空的 c29 拉到了 0 V 附近。

查完再接上 12 V 适配器，红表笔放 ②、黑表笔放 ③，用 2 V 挡，先把电位器转到约 0.169 V。这只是模型给的起点，真正的门限第 7 步再找（参数与调试篇 第二节说明了为什么）。

第 6 步：触发器、发射、接 Arduino（断电）

断电，按 ④ 接好 74HC74 的其余脚：j41、j42、j46 接下方 GND 轨；b44→b40；d41→d39、e39–f39、g39–g40；（j24、j29 两只 2.2k 上拉已在第 5 步插好，不要再插）；i24→i43、c29→c43、g44→a42，a45 接 D8。插两只 150 Ω（h50–h53、i52–i56），j50 接 D3，j52 接 D11。D4 先不接，发射探头也先不插，先做下面的手动检验。

手动检验 D 触发器（不用示波器）：原理与实现篇 第二节的真值表，可以在这里亲手验证一遍。

  1. 断电。把多备的那只 10k 从 j39 接到下方 +5 V 轨（/CLR 平时为 1，碰 GND 时为 0，电流只有 0.5 mA）。再拿一根黑跳线，一端插进下方 GND 轨，另一端先悬空，这根线下面叫「测试线」。
  2. 只插 USB，不接 12 V 适配器。这时 LM393 不工作，它的两个输出只靠 2.2k 上拉，都是 1；测试线去碰它们最多 2.3 mA。万用表 20 V 挡，红表笔放 ④（第 46 列上半）、黑表笔放 GND 轨。
  3. 测试线碰一下 h39 再拿开（清零）：④ 应约 5 V，即 /Q2 = 1。
  4. 测试线碰一下 d29 再拿开（CLK2 先变 0、再变回 1，是一个上升沿）：④ 应仍约 5 V。没武装，过零来了也不算。
  5. 测试线碰一下 h43 再拿开（/PRE1 = 0，武装，Q1 = 1）：④ 仍约 5 V，还没有时钟沿。
  6. 测试线再碰一下 d29 再拿开：④ 应从约 5 V 变成约 0 V。这就是「先武装、再过零」才捕获。
  7. 再碰一下 h39：④ 回到约 5 V。

如果第 6 小步 ④ 一直约 5 V 不变，按这个顺序查：e29–f29 跳线、j29 的 2.2k 上拉、c29→c43 跳线（这三处让 d29 的上升沿到达 CLK2）；再查 i24→i43 和 h43 是否真的碰到（武装是否生效）。如果第 3 小步 ④ 就不是约 5 V，先查 j39 那只 10k、g39–g40、e39–f39、d41→d39。如果第 4 小步 ④ 就变成约 0 V（还没武装就被「捕获」了），说明 /PRE1 一直是 0 或悬空：查 j24 的 2.2k 上拉和 i24→i43。

测试线只碰 h39、d29、h43 这三个孔，别的孔不要碰。做完断电，拔掉那只 10k 和测试线，从 j39 接 D4，发射探头接 f53、f56。

按图 37-p4-3 把两只探头用胶带固定在木条上，正对着、同一高度，正面到正面 20.0 cm。每只探头下面垫一小块泡沫，探头中心比木条表面高 2～3 cm：只高 1 cm 时，从木条表面反射的那一路只比直达声多走约 1.00 mm（约 2.9 µs），几乎同时到达，会改变回波形状和固定偏移；高 2.5 cm 时多走约 6.16 mm（约 17.9 µs），而且更弱。探头贴好以后，整个实验都不再动它们在木条上的位置（第 8 步挪接收探头时，连同它下面的泡沫整块挪）。

图 37-p4-3　俯视图：探头正对着、同一高度；风沿两只探头的连线吹

接回电源，打开串口监视器（115200）。应该看到 t_us 稳定在几百微秒（模型值约 707.79），miss=0。万用表 2 V 挡，红表笔放 ④、黑表笔放 GND 轨，应读约 0.708 V。

第 7 步：找你这对探头的最佳门限

先确认不跳周期，再测间距和风，所以这一步排在最前面。风扇关着，红表笔放 ②、黑表笔放 ③，把 V_TH 从 0.05 V 慢慢转，一直转到最大（约 0.545 V），每转一点都看串口 t_us（或 ④ 的读数）。你会看到读数一级一级地跳，每级约 25 µs（25 mV）。记下相邻两次跳变时的 V_TH，把电位器转回两者的中间：这就是你这对探头的最佳门限。转好后看 max − min 应只有几格。

如果转到最大还只看到一两级台阶，说明你的回波比模型大（参数与调试篇 第二节估计可能大两三倍）。这时断电，把门限网络的 100 kΩ（g33–g36）换成 47 kΩ（原理与实现篇 练习 3），接回电源（先 USB、再 12 V），V_TH 就能调到约 1.053 V，再扫一遍。

第 8 步：改变间距

带电即可，只挪动接收探头（连同下面的泡沫）。依次放在 17、19、21、23 cm，每个位置等读数稳定，记下 t_us；用万用表时记下 ④，紧接着再读一次 V5。

第 9 步：风扇（整根木条转向，开减关）

回到 20.0 cm。风扇插在单独的手机充电器上，按图 37-p4-3 放在发射探头后面 10～15 cm（从风扇出风面量到发射探头背面），比贴着放好（发射探头自己挡在风扇正前方，后面有一段尾流）。

  1. 方向 A（顺风）：关风扇读一次 → 开风扇等几秒读一次 → 再关风扇读一次。
  2. 方向 B（逆风）：探头在木条上不动，把整根木条连同两只探头水平转 180°，让接收探头朝向风扇，离风扇的距离和刚才一样（引线够长，慢慢转，别扯到面包板）；风扇和接线都不动。同样读「关 → 开 → 关」。
  3. 每个方向只用「开减关」（开的读数减去前后两次关的平均）。按本节模型，方向 A 约 −5.12 µs，方向 B 约 +5.13 µs，两者相减约 10.25 µs。

为什么这么麻烦？每 1 mm 声程是 2.913 µs，1 mm 的放置误差就相当于约 0.86 m/s 的风；而 3 m/s 的风让单向读数只变约 5 µs。把探头拆下来对调，重新贴的误差就和风一样大了。转木条时间距没变，固定偏移和探头差异都在「开减关」里抵消；每组「关 → 开 → 关」在半分钟内读完，温度也来不及变。

以串口 t_us 为准。万用表 ④ 的读数正比于 V5，而 V5 来自电脑 USB：它只要变 0.4 %（20 mV），④ 就变约 2.8 mV，差不多是单向风信号的一半；风扇如果插在同一台电脑上，一开一关 V5 就会跳。只用万用表时，每读一次 ④ 就马上读一次 V5，用 t = V④ ÷ V5 × 5000 µs 换算。

风扇吹出来的风不均匀，量到的是 20 cm 路径上的平均风速，比风扇标称风速小是正常的。

没有示波器怎么办

  • 串口 t_us 是主要读法：直接给出微秒数，分辨到 62.5 ns 再取 100 次平均，而且不受 V5 影响。
  • 万用表读 ④ 是备用读法：不用电脑也能看。/Q2 的平均电压就是一只「时间→电压」转换器，但 1 mV ≈ 1 µs 只在 V5 = 5.00 V 时成立；每读一次 ④ 都配一次 V5。用它核对串口：两者换算后之差应接近一个常数。
  • 看 min、max 认出跳周期：max − min 接近 400 就是在跳，按第 7 步重新找门限。
  • 串口绘图器：把打印改成只打印 avg / 16.0，开关风扇时能看到曲线上下台阶。

用 Python 核对你的读数

把你量到的数填进下面的变量（现在填的是模型的预期值），运行后它会算出声速和风速，并检查你的读数是否合理。代码只做计算和打印，不写任何文件。

# 1. 填入你的实测值（串口 t_us，单位 µs；现在填的是模型的预期值）
L_CM = [17, 19, 21, 23]                  # 第 8 步的间距（cm）
T_L = [620.3, 678.5, 736.9, 795.2]       # 对应的 t_us（µs）
L_FAN = 0.200                            # 第 9 步的间距（m）
# 第 9 步：方向 A（顺风）关、开、关；方向 B（逆风，整根木条转 180°）关、开、关
A_OFF1, A_ON, A_OFF2 = 707.79, 702.67, 707.79
B_OFF1, B_ON, B_OFF2 = 707.79, 712.92, 707.79

# 只用万用表时：每个 ④ 读数 mV 配一个同时读的 V5（V），用这个函数换成 µs 再填上面
def mv_to_us(mv, v5):
    return mv * 1e-3 / v5 * 5e-3 * 1e6   # 一轮 5 ms

# 2. 计算
xs = [l * 10 for l in L_CM]                   # cm → mm
n = len(xs)
mx, my = sum(xs) / n, sum(T_L) / n
slope = sum((x - mx) * (y - my) for x, y in zip(xs, T_L)) / sum((x - mx) ** 2 for x in xs)   # µs/mm
offset = my - slope * mx                      # µs：首达之外的固定偏移
c = 1e3 / slope                               # m/s
dA = A_ON - (A_OFF1 + A_OFF2) / 2             # 方向 A 开减关（µs），应为负
dB = B_ON - (B_OFF1 + B_OFF2) / 2             # 方向 B 开减关（µs），应为正
dt = dB - dA                                  # 逆风比顺风慢多少（µs）
v = dt * 1e-6 * c ** 2 / (2 * L_FAN)
t0 = (A_OFF1 + A_OFF2 + B_OFF1 + B_OFF2) / 4 - offset   # 无风的首达时间（µs）
t1, t2 = (t0 + dA) * 1e-6, (t0 + dB) * 1e-6
v2 = L_FAN / 2 * (1 / t1 - 1 / t2)            # 两时间法
print(f"斜率 {slope:.4f} µs/mm → 声速 {c:.1f} m/s；固定偏移 {offset:.1f} µs")
print(f"开减关：A {dA:+.2f} µs，B {dB:+.2f} µs；Δt {dt:.2f} µs → 风速 {v:.2f} m/s；两时间法 {v2:.2f} m/s")

# 3. 检查
assert 320 < c < 370, "声速不在 320–370 m/s：检查间距是否量的是正面到正面，或是否跳了周期"
assert 0 < offset < 400, "固定偏移不合理：检查是否有一个间距跳了周期（看串口 max − min）"
assert abs(dt) < 20, "两个开减关相差超过 20 µs：多半有一次跳了周期，回第 7 步重新找门限"
assert dA < 0 < dB, "顺风应变快、逆风应变慢：检查风扇方向和木条是否转了 180°"
assert 0.3 < v < 8, "风速不在 0.3–8 m/s：检查风扇是否沿两只探头连线吹"
assert abs(v2 - v) / v < 0.1, "两种算法差超过 10 %：检查偏移和读数"
print("读数合理 ✓")

如果某一条 assert 报错，按它的提示和 参数与调试篇 第七节的排错表去查。

  1. 第 8 步如果把间距一下拉到 30 cm，读数会落在图 37-p4-4 左图那条直线的延长线上吗？
揭晓

多半不会，会比延长线高约 25 mV。间距变大，回波变小，原来卡在第 5 个周期的武装推迟到第 6 个周期，整整晚一个周期。按本节模型，30 cm 的残差是 +24.9 µs。所以量斜率时间距只在小范围里改。

  1. 第 9 步测逆风时，为什么不把两只探头从木条上拆下来对调，而是整根木条转 180°？
揭晓

因为放置误差和要测的信号一样大。每 1 mm 声程是 2.913 µs，相当于约 0.86 m/s 的风；而 3 m/s 的风让单向读数只变约 5 µs。重新贴探头差 1～2 mm 很平常，量出来的「风」就可能是 1.5 m/s 也可能是 5 m/s，而且 Python 的检查也发现不了。两只探头的个体差异（灵敏度各 ±3 dB）还可能让固定偏移整个变掉，甚至跳一个周期。整根木条转向时，间距、固定偏移、探头差异都不变，「开减关」把它们都减掉了。真正的流量计是让两只探头轮流发、轮流收，也是同一个思路：不动几何，只换方向。

  1. 同学 A 说：「顺风比关风扇快了 5 mV，所以只量顺风这一次就够了。」这样做有什么风险？
揭晓

温度。20 cm 声程每升高 1 °C 就快约 0.994 µs，也就是约 1 mV；风扇吹的是室内空气，温度稍有不同，或你的手靠近了，几度的变化就能把 5 mV 吃掉。所以第 9 步每个方向都读「关 → 开 → 关」，只用开减关，温度变化在半分钟里来不及影响多少。另外，风扇的风到 20 cm 路径上并不均匀，发射探头还挡住了一部分，量到的是路径平均风速，比风扇标称值小是正常的。
